# Target: Crossbar.io, single node

One [Crossbar.io](https://crossbar.io) router, three realms, and nine [AutobahnPython](https://github.com/crossbario/autobahn-python) clients running a seeded workload. The router configuration and the client code are published here in full. Only the keys stay out of the repository.

## The system under test

Everything in the path of a WAMP call is part of the target: the protocol stack, the interpreter, the TLS library and the event loop. Each of them affects behaviour and performance, and each can carry a bug or an exploit.

| layer | router | clients |
|---|---|---|
| machine | one KVM/QEMU virtual machine, Debian 13 | one KVM/QEMU virtual machine per client (nine), Debian 13 |
| host | Debian 12 | the same host |
| network | TCP between the virtual machines | |
| interpreter | CPython 3.14 | CPython 3.14 |
| software | Crossbar.io on Twisted, epoll reactor (`CROSSBAR_REACTOR=epoll`) | AutobahnPython on asyncio, `_UnixSelectorEventLoop` with `EpollSelector` |
| TLS | pyOpenSSL over `cryptography`, which bundles **its own OpenSSL** | the CPython `ssl` module, with **the OpenSSL CPython was built with** |
| WAMP transport | WebSocket over TLS, no WebSocket extensions (no compression); RawSocket over TLS is also offered | WebSocket over TLS |
| serializer | CBOR | CBOR |
| authentication | anonymous (`public`), WAMP-Cryptosign (`application1`, `application2`) | the same |

**The two ends of a connection run different TLS stacks.** The router's TLS goes through the OpenSSL that `cryptography` bundles; the clients' TLS goes through the OpenSSL CPython was built with. Their versions differ.

**Every run records what it actually ran on.**
- Each client writes a `start` record into its log, holding the interpreter, the OpenSSL version, the library versions and the event loop.
- Each `join` record holds the WebSocket extensions actually negotiated on the live connection; there must be none.
- The smoke test prints the router's stack next to the clients' stack.

The smoke test on 2026-11-13 measured:

| | router | clients |
|---|---|---|
| interpreter | CPython 3.14.7 | CPython 3.14.7 |
| TLS | OpenSSL 4.0.3 (`cryptography` 50.0.2, pyOpenSSL 26.4.0) | OpenSSL 3.5.8 |
| WAMP | Crossbar.io 26.11.1.dev2, AutobahnPython 26.11.1, Twisted 26.10.0 | AutobahnPython 26.11.1, txaio 26.6.1 |
| CBOR, Cryptosign | cbor2 6.2.1, PyNaCl 1.6.2 | cbor2 6.2.1, PyNaCl 1.6.2 |

This measurement comes from the test machine. The deployed virtual machines record their own values, and a match result carries them.

The smoke test's call latencies show that the target works. They are not a benchmark: measuring robust round-trip times, such as a p99, is a separate task, and so are faster variants of the target (for example PyPy).

## The router

[`.crossbar/config.json`](.crossbar/config.json) defines one listening transport of type `universal`, on port 8080 over TLS. On every connection the router tells three protocols apart:

- **WAMP over WebSocket**, at path `/ws`;
- **WAMP over RawSocket**, on the same port;
- **HTTPS**: the static files in [`web/`](web/), the web share.

WAMP uses the CBOR serializer. There are three realms with three clients each:

| realm | authentication | role | clients |
|---|---|---|---|
| `public` | anonymous | `guest` | `client01`, `client02`, `client03` |
| `application1` | WAMP-Cryptosign | `device` | `client04`, `client05`, `client06` |
| `application2` | WAMP-Cryptosign | `device` | `client07`, `client08`, `client09` |

Each role may call, register, publish and subscribe under the URI prefix `gladiators.`, and nowhere else. Caller and publisher disclosure is on, so a callee sees the caller's authid as the router reports it.

### Keys

There is no key material in this repository.

- **The TLS key and certificate** (`.crossbar/server.key`, `.crossbar/server.crt`) are generated by each deployment. For a local run, make a self-signed pair for `localhost`:

  ```console
  openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes -keyout .crossbar/server.key -out .crossbar/server.crt -days 30 -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost"
  ```

- **The Cryptosign principals** `client04` to `client09` start with empty `authorized_keys`. Each client generates its own key, and only its public key goes into `config.json`. While the list is empty, the router refuses that principal.

## The client

Each client runs [`client/workload.py`](client/workload.py). It needs AutobahnPython with asyncio, CBOR and Cryptosign support; see [`client/requirements.txt`](client/requirements.txt).

A client:

1. joins its realm, anonymously or with its Cryptosign key, and reconnects forever if the connection drops;
2. registers `gladiators.<name>.echo`, which returns `{payload, callee, caller_seen}`;
3. subscribes to `gladiators.tick`;
4. in a loop driven by `--seed`, calls a random peer's `echo` with a payload of 16 to 1024 bytes (`--rate` calls per second on average), and publishes a tick carrying its realm and its name on about every second iteration;
5. checks every answer:
   - the payload comes back unchanged;
   - the answer comes from the peer it called;
   - the router reported the caller's own authid to the callee;
   - every tick it receives comes from its own realm.

With `--duration` the client stops in two phases: it stops calling, waits for its call in flight, keeps answering `echo` for `--stop-grace` seconds (default 5) while its peers finish, and only then leaves.

Every event becomes one JSON line in `--log`, with an fsync after each line: connect, join, refused join, call, publish, received tick, leave, disconnect, and a final summary. A record carries a timestamp, the operation, the peer, the latency in ms, `ok` or the error, and a `violation` field whenever a check fails. Call latency (for example the p99) and the error rate come straight out of these logs.

Prove that every check fires on its own case:

```console
python client/workload.py --self-test
```

Create a client key (mode 0600) and print its public key:

```console
python client/workload.py --generate-key client04.key
```

Run a client:

```console
python client/workload.py --name client04 --realm application1 --key client04.key --peers client05,client06 --url wss://localhost:8080/ws --trust .crossbar/server.crt --seed 1 --log client04.jsonl
```

Use `--url rss://localhost:8080` for RawSocket. Without `--key` the client authenticates anonymously, which only the realm `public` admits.

## Smoke test

[`smoke.sh`](smoke.sh) runs the whole target on one machine:

1. it copies the node directory to a temporary directory;
2. it generates a throwaway TLS pair and throwaway client keys there;
3. it starts the router on the epoll reactor and the nine clients for `DURATION` seconds (default 120), and prints the stack of both ends;
4. it requires every client log to show calls and ticks from its own realm, with no errors and no violations, and every WebSocket connection to have no extensions negotiated;
5. it requires the router to refuse an unknown Cryptosign key (`wamp.error.not_authorized`) and an anonymous client in `application1` (`wamp.error.no_such_role`).

```console
PYTHON=/path/to/venv/bin/python CROSSBAR=/path/to/venv/bin/crossbar ./smoke.sh
```

It listens on port 8080 (`PORT` changes that). To keep it off the host's network, run it in its own network namespace:

```console
unshare -rn --pid --fork --mount-proc ./smoke.sh
```

From the repository root, `just smoke` does the same.
